  <name>Task 2: Identity disambiguation guard and candidate matching service</name>
  <files>backend/services/deterministic_engine.py, tests/test_identity_disambiguation.py</files>
  <action>
Implement customer lookup and disambiguation guard in backend/services/deterministic_engine.py per D-03:
- resolve_customer_identity(conn, query_name: str) -> dict: Searches customers table using exact match on name or JSON aliases, falling back to case-insensitive substring match.
- If exactly 1 customer matches: returns dict with status='EXACT_MATCH', customer details, current_udhaar, and last_visit_date.
- If 0 customers match: returns dict with status='NOT_FOUND' and query_name.
- If >1 customers match (e.g. 'Suresh' matching 'Suresh Patil (Tailor)' and 'Suresh Kadam (Kirana)'): halts automatic write actions and returns status='NEEDS_DISAMBIGUATION', ambiguity_reason='Found N customers matching in shop memory.', candidates list (each item containing customer_id, name, phone, current_udhaar calculated via calculate_customer_balance, and last_visit formatted), why_am_i_seeing_this='KiranaOS blocks blind writes when customer names overlap.', and bilingual prompt suggestions per PRD §7.1.
Create tests/test_identity_disambiguation.py asserting that unique customer queries resolve cleanly, multiple matches trigger NEEDS_DISAMBIGUATION with candidate udhaar balances, and missing customers return NOT_FOUND per D-03.
