<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public Link Webhook Caller → `/simulate-link-paid/{slug}` & `/simulate-promo-click/{slug}` | External or demo webhook requests attempting to replay payments or forge unknown slugs |
| Merchant Input → `/dead-stock-campaign` | Negative or excessive discount values that could erode retail margins below wholesale cost |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-04 | Spoofing / Replay | backend/routers/cmo_router.py | high | mitigate | Enforce idempotency on `campaigns_and_links.status == 'PAID'` and unique `provider_ref` in `ledger_entries` before appending `REPAYMENT_JAMA` |
| T-04-05 | Tampering | backend/routers/cmo_router.py | high | mitigate | Validate `proposed_discount_rupees >= 0` with Pydantic and enforce `calculate_breakeven_offer` hard stop (`OFFER_BLOCKED_LOSS_MAKING`) when `M_new <= 0`; wrap payment clearing + ledger + audit writes in atomic SQLite transaction |
| T-04-06 | Information Disclosure | backend/routers/cmo_router.py | medium | mitigate | Validate `customer_id`, `item_id`, and link `slug` existence returning 404 without leaking raw SQL exceptions or API keys |
| T-04-SC | Tampering | FastAPI, Pydantic, SQLite3 | high | mitigate | Use standard FastAPI/Pydantic validation and parameterized SQL queries (`?`) across all CMO queries |
