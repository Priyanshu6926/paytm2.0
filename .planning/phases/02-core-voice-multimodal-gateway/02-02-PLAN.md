  <files>backend/services/voice_intent_parser.py, tests/test_voice_gateway.py</files>
  <action>
Implement the dynamic biasing extractor and rule-based Kirana shop intent parser in backend/services/voice_intent_parser.py per D-03 and D-04:
1. Implement extract_keyterm_biasing_from_db(conn) -> list[str]:
   - Queries customers table for all names and parsed JSON aliases.
   - Queries inventory_items table for sku_name and parsed JSON local_aliases.
   - Merges and deduplicates into a clean list of phonetic prompt terms (e.g., "Ramesh Sharma", "Suresh Patil", "Suresh Kadam", "Amul Pure Ghee", "Fortune Sunlite Oil", "Haldiram Aloo Bhujia").
2. Implement parse_voice_intent(transcript: str, language_hint: str = "hi-IN", conn=None) -> dict:
   - Extracts numeric monetary amounts (regex matching numbers preceding or succeeding "rupaye", "rupees", "rs", "₹", "udhaar", "jama").
   - Classifies intent into: CREDIT_UDHAAR ("udhaar", "baki", "likho"), REPAYMENT_JAMA ("jama", "wapas", "chukaya", "diye"), STOCK_IN ("aaya", "packet aaya", "stock in"), STOCKOUT_FLAG ("khatam", "stockout"), QUERY ("khata dikhao", "hisab").
   - Resolves customer name using deterministic_engine.resolve_customer_identity(conn, extracted_name).
   - If AMBIGUOUS: returns status="NEEDS_DISAMBIGUATION" with candidates list, ambiguity_reason, why_am_i_seeing_this evidence pill, and spoken_prompt_hi per PRD §7.1 (e.g., "Dukaan mein do Suresh hain: Suresh Tailor ya Suresh Kirana? Kiske khate mein 200 likhoon?").
   - If RESOLVED: returns status="PROPOSAL", extracted_amount, customer details, current balance, why_am_i_seeing_this calculation pill, and spoken_prompt_hi.
3. Start tests/test_voice_gateway.py verifying extract_keyterm_biasing_from_db extracts Dadar demo store terms and parse_voice_intent correctly parses Suresh disambiguation and Ramesh repayment phrases.

<task type="auto">
  <name>Task 2: Full Voice Gateway router with /propose, /confirm, /tts, and /health endpoints mounted in FastAPI</name>
  <files>backend/routers/voice_router.py, backend/main.py, tests/test_voice_gateway.py</files>
  <action>
Implement backend/routers/voice_router.py and register in backend/main.py per D-04 and D-05:
1. Create APIRouter(prefix="/api/v1/voice", tags=["voice"]).
2. Implement POST /propose:
   - Supports application/json (transcript_override, language_hint) AND multipart/form-data with file upload.
   - If audio uploaded: extracts DB keyterms, calls sarvam_engine.transcribe_audio with biasing prompt, obtains transcript.
   - Calls voice_intent_parser.parse_voice_intent(transcript, language_hint, conn).
   - Synthesizes spoken prompt audio via sarvam_engine.synthesize_speech and attaches tts_audio_base64 to the response.
   - Returns unconfirmed Proposal Card (or Disambiguation Card).
3. Implement POST /confirm:
   - Accepts ProposalConfirmRequest (proposal_id, intent, customer_id, amount, item_id, quantity_delta, action="APPROVE").
   - Enforces action == "APPROVE" (rejects unconfirmed writes).
   - Executes deterministic write via deterministic_engine: add_credit_entry or add_repayment_entry or add_stock_event.
   - Logs an auditable entry into business_events table (category="LEDGER", actor="MERCHANT_APPROVED", structured evidence JSON).
   - Synthesizes spoken confirmation audio via sarvam_engine.synthesize_speech.
   - Returns status="CONFIRMED", new_balance, ledger_entry_id, and tts_audio_base64.
4. Implement POST /tts: accepts TextToSpeechRequest(text, target_language_code, speaker) and returns synthesized audio payload.
5. Implement GET /health: returns gateway status, active database connection, and Sarvam engine health.
6. Register voice_router in backend/main.py using app.include_router(voice_router).
7. Complete tests/test_voice_gateway.py with FastAPI TestClient verifying:
   - GET /api/v1/voice/health returns healthy.
   - POST /api/v1/voice/propose with transcript_override="Suresh ka 200 rupaye udhaar likh do" returns NEEDS_DISAMBIGUATION.
   - POST /api/v1/voice/propose with transcript_override="Ramesh ne 300 rupaye jama kiye" returns PROPOSAL with amount=300.
   - POST /api/v1/voice/confirm approves Ramesh repayment, writes to ledger, updates balance, and logs business event.
   - POST /api/v1/voice/tts generates audio response with valid base64.
  </action>
